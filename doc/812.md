# 华农掌中行（wechat-geo）

华南农业大学校园导航微信小程序，包含 POI、路线规划、校巴、充电桩、停车场、赏花、收藏和校园资讯等功能。本文档同时是开发者与后续智能体的交接文档。

## 项目结构

```text
wechat-geo/
├─ admin/                        独立管理后台前端
│  ├─ admin-login.html           管理后台登录页
│  ├─ admin-dashboard.html       管理后台主页
│  └─ package.json               管理后台启动配置
├─ back/                         Node.js + Express + MySQL 后端
│  ├─ routes/                    按业务划分的 API
│  ├─ config/index.js            端口、数据库连接与部分表初始化
│  ├─ tasks/scheduled.js          充电业务定时任务
│  └─ server.js                   后端入口和路由注册
├─ front/                        微信小程序
│  ├─ api/                       小程序 API 封装
│  ├─ pages/                     业务页面
│  ├─ utils/                     请求、地图和 GIS 工具
│  ├─ app.json                   页面注册与全局配置
│  └─ config.js                  API、WebSocket 和地图配置
└─ sql/
   ├─ huanong_palm_backup.sql     完整建库备份
   └─ 20260812_feature_update.sql 已有数据库的一次性增量迁移
```

## 技术栈

- 微信原生小程序（WXML / WXSS / JavaScript）
- Node.js + Express 4
- MySQL 8，使用 `mysql2/promise`
- JWT、bcrypt、WebSocket、Multer
- 腾讯位置服务（小程序地图 SDK）

## 本地启动

### 1. 准备 MySQL

新环境直接导入：

```sql
SOURCE C:/wechat-geo/sql/huanong_palm_backup.sql;
```

如果数据库已存在且尚未应用 2026-08-12 的改动，只执行一次：

```sql
SOURCE C:/wechat-geo/sql/20260812_feature_update.sql;
```

`20260812_feature_update.sql` 会：

- 给 `poi` 新增 `comment`。
- 删除 `poi_rating`。
- 将常用路线、充电建议和公交订阅的用户外键统一指向 `users(id)`。

> 增量迁移不是幂等脚本，不要重复执行。新建库导入完整备份后，不要再执行增量迁移。

### 2. 启动后端

```powershell
Set-Location C:\wechat-geo\back
Copy-Item env.example .env
npm install
npm run dev
```

按实际环境修改 `back/.env`：

```dotenv
PORT=3000
WS_PORT=3001
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=your_password
DB_NAME=huanong_palm
JWT_SECRET=replace_me
```

### 3. 运行小程序

1. 在微信开发者工具中导入 `front/`。
2. 在 `front/config.js` 配置 `apiBaseUrl` 和地图 Key。
3. 确保 API 端口与后端 `PORT` 一致。

当前存在一个需要特别注意的配置差异：

- `back/config/index.js` 默认端口是 `3000`。
- `front/config.js` 当前 API 是 `http://localhost:4000/api`。

请通过 `.env` 把后端改为 `PORT=4000`，或将小程序 API 改为 `http://localhost:3000/api`。真机调试时 `localhost` 指向手机本身，需替换为局域网 IP 或 HTTPS 域名，并在微信后台配置合法域名。

## 核心数据模型

当前完整备份包含 18 张表：

- 账号：`users`、`admin`
- POI：`poi`、`user_favorites`
- 公交：`bus_line`、`bus_stop`、`bus_line_stop`、`bus_arrival_subscription`
- 充电：`charging_station`、`charging_reservation`、`charging_record`、`charging_plan_suggestion`
- 赏花：`flower_spots`、`flower_routes`、`flower_checkins`
- 路线与出行：`frequent_route`、`parking_lot`
- 资讯：`news`

已确认的数据库约定：

- 用户表只使用复数名 `users`；旧 `user` 已删除。
- 收藏表只使用 `user_favorites`；旧 `favorite` 已删除。
- POI 点评直接保存在 `poi.comment`，综合评分在 `poi.rating`；不再使用 `poi_rating`。
- `bus_line_stop` 是公交线路和站点的多对多顺序表，不应合并。
- 充电站、预约和实际充电记录是不同生命周期，不应合并。

## 主要 API

所有公开 API 以 `/api` 为前缀。

| 模块 | 关键路径 | 说明 |
| --- | --- | --- |
| 登录 | `POST /auth/register` / `POST /auth/login` | 手机号账号 |
| POI | `GET /poi/list` / `GET /poi/detail/:id` | POI 列表和详情 |
| 收藏 | `POST /favorites/add` / `POST /favorites/remove` | 使用 `user_favorites` |
| 常用路线 | `POST /route/save` | 保存路线 |
| 常用路线 | `GET /route/my-routes?userId=` | 按用户查询 |
| 常用路线 | `DELETE /route/delete` | Body 需 `routeId` 和 `userId` |
| 停车场 | `GET /parking/list?type=` | `bike` / `ebike` / `car` |
| 停车场 | `GET /parking/detail/:id` | 停车场详情 |
| 充电建议 | `POST /charging/suggestion` | 位置与建议原因 |
| 充电建议 | `GET /charging/suggestions?userId=` | 查看个人提交记录 |
| 公交 | `GET /bus/lines` / `POST /bus/subscribe` | 线路与到站订阅 |
| 赏花 | `GET /flower/spots` / `POST /flower/checkin` | 赏花点和打卡 |

路由总表以 `back/server.js` 和 `back/routes/*.js` 为准。

## 已知问题与后续优先级

1. **认证方式不统一**：多数业务接口仍直接信任前端传入的 `userId`，没有从 JWT 中取用户。上线前应增加用户鉴权中间件，并移除客户端可伪造的用户 ID。
2. **管理 CRUD 权限**：`admin-manage.js` 的多个接口未显式使用 `adminAuth`，需要安全审查。
3. **端口不一致**：前端默认 `4000`，后端默认 `3000`，启动前必须统一。
4. **地图 Key**：`front/config.js` 仍是占位 Key，路线规划和逆地理编码需真实腾讯地图 Key。
5. **停车场数据重复**：应在确认现有库数据后清理重复行，并考虑增加唯一索引。当前只在查询层去重。
6. **数据库初始化不完整**：`back/config/index.js:initDatabase()` 只创建部分表，完整结构仍以 SQL 备份为准。
7. **编码历史问题**：项目部分注释或字符串曾出现 UTF-8/GBK 乱码。本次已修复 `front/app.json` 和新页面 JSON；修改其他文件时应保持 UTF-8。
8. **没有自动化测试**：当前只做了 JavaScript 语法和 JSON 解析校验，还需在连接 MySQL 和微信开发者工具后做端到端验证。

## 交接检查清单

后续智能体开始修改前，建议按以下顺序复核：

1. 阅读本 README、`back/server.js`、`front/app.json` 和本次增量 SQL。
2. 确认现有库是“新导入完整备份”还是“旧库待迁移”，不要重复执行增量 SQL。
3. 检查 `.env` 与 `front/config.js` 的端口、数据库、地图 Key 和 WebSocket 配置。
4. 使用 `rg` 检查是否重新引入 `user`、`favorite` 或 `poi_rating`。
5. 改动后至少执行：

```powershell
Get-ChildItem back\routes,back\tasks,back\config,front\api,front\pages -Recurse -Filter *.js |
  ForEach-Object { node --check $_.FullName }

Get-ChildItem front -Recurse -Filter *.json |
  ForEach-Object { Get-Content $_.FullName -Raw -Encoding utf8 | ConvertFrom-Json | Out-Null }
```

6. 需要调整表结构时，同时更新完整备份和新的增量迁移，不要只修改运行中数据库。
